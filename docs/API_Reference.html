NSD.Lib – NES Sound Driver & MML Compiler

API Reference

本ページでは、NSD.Lib サウンドドライバの API 仕様をまとめて説明します。
関数仕様、内部データ構造、制御モデルを把握するためのリファレンスページです。

This page provides the API reference for the NSD.Lib sound driver.

設計ポリシー／Design Policy

NSD.Lib は、NES 実機開発における一般的なフレーム駆動モデルを前提として設計されています。

サウンドドライバは自律的に再生処理を進めることはせず、 ゲーム側から 1 フレームごとに明示的に更新 API を呼び出す ことで再生状態が進行します。

これにより、NMI 割り込み内での PPU 更新処理との共存や、 メモリバンク切り替えを伴う構成にも柔軟に対応できます。

再生時の CPU 負荷やデータサイズの最適化は、 主に付属の MML コンパイラ側で行う設計となっており、 コンパイル時に不要なコマンドの削減や再生シミュレーションを通じた最適化が行われます。

API は、NES の限られた CPU 資源・メモリ空間を前提に、 挙動が明確で制御しやすい構成を重視しています。

ラベルとセグメント名／Name of Label & Segment

ライブラリ本体が使うラベル名

NSD.Lib が提供する API 関数および関連シンボルは、 _nsd_ プレフィックス （アセンブリ言語レベルでの内部シンボル名）を使用しています。
C 言語から参照する場合は、先頭の _ を除いた nsd_ で参照できます。

これは、他のライブラリやユーザーコードとのシンボル衝突を避けるための設計です。

C 言語から呼び出す API 関数、ならびにアセンブリ言語レベルで参照される ラベルについても、同一の命名規則が適用されています。

ライブラリ本体が使用するセグメント

本ライブラリは、以下のセグメントを使用します。
リンカーのコンフィグファイルで、必ず本セグメント領域を定義してください。
※ C 言語からコンパイルされるアセンブリ言語ソースで用いられる セグメント名に合わせています。

セグメント名 内容
CODE サウンドドライバのプログラム本体です。
RODATA 固定データ領域です。
音程テーブルやオペコード毎のジャンプテーブル等が含まれます。
BSS 制御用ワークエリア（非ゼロページ）です。
ZEROPAGE 制御用ワークエリア（ゼロページ）です。
※ リンカーの -t nes オプションでは 本ドライバが必要とする Zeropage 容量を確保できません。

曲データのラベル・セグメント名

付属の MML コンパイラを用いて楽曲制作を行う場合、 MML ソース内で、曲データを配置するセグメントや使用するラベル名を 指定することが可能です。
これにより、1 つのプロジェクト内で、 複数の MML から生成したオブジェクトをリンクできます。

付属の MML コンパイラが出力するアセンブリ言語ソースは、 ソースを編集することなく、そのままアセンブル・リンク可能です。
詳細は nsc.exe が出力するアセンブリ言語ソースについて を参照してください。

以下は C 言語での使用を想定した説明ですが、 アセンブリ言語からの利用方法も基本的な考え方は同じです。

C 言語でアプリケーションを開発する場合の注意

本サウンドドライバは、6502 の Zeropage 領域 （0x0000～0x00FF）を一定量使用します。
使用量は、有効にする拡張音源の種類によって異なります。

そのため、リンカー用の config ファイルを別途作成し、 -t none オプションでビルドしてください。

-t nes オプションでは、 C 言語ランタイムが使用する分のみ Zeropage が定義されており、 本ドライバ用の領域を確保できないため、ビルドに失敗します。

cc65 付属 NES 用ライブラリ「nes.lib」を使用する場合の注意

cc65 付属の NES 用ライブラリ nes.lib には、 config ファイルのセグメント定義とは無関係に、 Zeropage を絶対アドレスでアクセスするコードが含まれています。

そのため、config ファイルの設定次第では、 NSD.Lib が使用する Zeropage 領域と競合する可能性があります。

リンカー用 config ファイルを作成する際は、 cc65 付属のドキュメント、 nes.inc および nes.lib のソースを 十分に確認してください。

関数呼出規約／Calling Convention

NSD.Lib の API 関数は、すべて __fastcall__ 呼び出し規約で実装されています。

レジスタの保存・破壊規則、および引数の受け渡し方法は、 cc65 が定義する fastcall 規約に従います。

※ 呼び出し規約の詳細は cc65 の公式ドキュメントを参照してください。

Driver Update Model

NSD.Lib のサウンドドライバは、 自律的に再生処理を進める方式ではありません。

ゲーム側から 1 フレームごとに API を呼び出すことで、 BGM や効果音の再生状態が更新されます。

通常は nsd_main() を使用しますが、 BGM と SE を異なるメモリバンクに配置する構成に対応するため、 個別更新用の関数も用意されています。

関数一覧／Function List

Function Description
nsd_init(void) サウンドドライバを初期化します。
nsd_set_dpcm(nsd_dpcm* dpcm) DPCM サンプル情報をドライバに設定します。
nsd_main(void) BGM と SE をまとめて更新するメイン処理（同一メモリバンク構成向け）。
nsd_main_bgm(void) BGM 再生処理のみを更新します（BGM と SE が別メモリバンクに配置されている場合）。
nsd_main_se(void) 効果音（SE）再生処理のみを更新します（BGM と SE が別メモリバンクに配置されている場合）。
nsd_play_bgm(void *bgm) 指定した BGM データの再生を開始します。
nsd_stop_bgm(void) 再生中の BGM を停止します。
nsd_pause_bgm(void) 再生中の BGM を一時停止します。
nsd_resume_bgm(void) 一時停止中の BGM を再開します。
nsd_play_se(void *se) 指定した効果音データを再生します。
nsd_stop_se(void) 再生中の効果音を停止します。
nsd_save(void *buff) サウンドドライバの内部状態をバッファへ保存します。
nsd_load(void *buff) 保存されたサウンドドライバの状態を復元します。
